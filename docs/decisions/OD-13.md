# OD-13 — UI language

**Status:** APPLIED (default) — confirm with owner
**Owner:** Product
**Needed by:** Phase 1
**Blocks:** Frontend i18n setup, content layout

## Question

Is the UI English only, Bangla only, or both?

## Applied answer

**Both, with English as the default.** The switcher is visible in the app shell.

The schema already carries `locale` where it matters — `faq_entries.locale`,
`faq_aliases` (which resolve Banglish spellings), `tour_steps.locale`, and
`message_templates`. The default locale for a business is on the business row.

## Consequences already built in

- FAQ aliases exist specifically so a Banglish spelling ("order koto te order
  korchi?") and the Bangla script spelling of the same question resolve to one entry.
  This is the same question in two scripts — not two questions.
- Tour steps carry a locale, so the product tour can be shown in the language the
  staff member reads.
- Templates are stored per locale, so a business can send a review request in the
  customer's language without a second template.

## Cost

English-first UI with Bangla content available, rather than a fully translated UI.
A fully bilingual interface doubles the string catalogue and the layout review for
every screen, and the audience for this product is business owners and staff — the
*customer-facing* text is what actually needs Bangla.
