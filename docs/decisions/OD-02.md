# OD-02 — Qualifying-order rules, Returning vs Repeat

**Status:** APPLIED (default) — revisit if the owner changes it
**Owner:** Product
**Needed by:** Phase 1
**Blocks:** CG-01, CG-02, bubble qualification

## Question

Which orders count towards a customer's totals and repeat status, and what separates
"Returning" from "Repeat"?

## Applied answer

**Qualifying order:** status is `paid` or `completed`. Excluded: `cancelled`,
`returned`, and orders refunded in full. A partially refunded order still qualifies and
counts its **net** amount (total minus refund).

**Returning customer:** at least one qualifying order.
**Repeat buyer:** at least two qualifying orders.

Both are derived from authoritative history and recomputed on each sync, never
incremented (CG-09).

## Options considered

| Rule set | Simple | Matches cash reality | Cost |
|---|---|---|---|
| A. paid or completed, refunded excluded | yes | partially — full refunds still count | low |
| B. paid or completed, net of refunds | no | yes | slightly higher |
| C. completed only | yes | no — paid-but-not-dispatched orders miss | low |

Chosen B. It is the only one where `total_spend` reconciles with the business's bank
statement.

## Where it lives

`customer_orders.qualifying` (bool) and `customer_orders.qualifying_rule_version`
(str). The rule set is **versioned**: a sync records which version produced each
flag, so a later rule change is auditable rather than retroactive. The rule itself
lives in `business_settings.qualifying_order_rules`, not in code — changing it is a
data change, not a migration.
