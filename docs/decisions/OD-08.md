# OD-08 — Review defaults

**Status:** APPLIED (default)
**Owner:** Product
**Needed by:** Phase 3
**Blocks:** review scheduling, reply window

## Question

What are the default review delay, send window, reply window, and request frequency?

## Applied answer

| Setting | Default | Why |
|---|---|---|
| Delay after order | **3 days** | long enough to have used the product; short enough that the memory is fresh |
| Send window | **09:00–20:00** local | outside it, the message reads as spam and delivery rates fall |
| Reply window | **14 days** | the customer may reply at leisure; the request stays open for this long |
| Requests per order | **1** | a second request for the same order is spam, and it breaks the review count |

The send window is evaluated in the **business's** timezone (`businesses.timezone`),
not the platform's, and not UTC.

These are defaults per business, overridable in `review_settings`. The current values
live in `core/config.py` as the seeded defaults; a business row overrides them.

## Interaction with OD-05

The free-reply window and the review reply window are different things. The reply
window (14 days) is how long *this app* keeps waiting for the customer's review reply.
The provider's free-reply window (OD-05) is how long *the platform* accepts a reply.
Where they conflict, the platform's window wins for outbound sends — a review request
sent outside it will not arrive.
