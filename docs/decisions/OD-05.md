# OD-05 — Channel eligibility per provider

**Status:** OPEN — build proceeds; eligibility is data, not code
**Owner:** Engineering
**Needed by:** Phase 0 (blocking)
**Blocks:** Restore Product and Review reachability; RP-08; the free-reply window

## Question

Under what conditions may this app send a message on each channel?

## Why it matters

Restock and review messages usually go out **days** after the last chat, which is
typically outside Messenger's and WhatsApp's short free-reply windows. If the rules are
wrong, messages silently never arrive — the worst possible failure, because the system
reports success.

The eligibility rules also decide whether a "free reply" from a customer still counts
toward the review-request window, and whether the customer can be re-contacted at all.

## Investigation still required

| Channel | What to verify |
|---|---|
| Messenger | Current messaging-policy window rules; what happens to a tag outside the window; the tag/message/response limits |
| WhatsApp Business | Template requirements and approval lead time; the session window and its reopening rules; per-template category restrictions |
| SMS | Gateway opt-out handling (STOP / STOPALL / START); whether the sender id is registered; DLT-style registration requirements if any |
| Email | Authenticated-domain requirements (SPF/DKIM/DMARC); which marketing vs transactional content each provider allows |

Also: the lead time for Meta app review and business verification. It is on the order
of weeks and must be planned around.

## Applied default

Until verified, **Email and SMS are the default channels**, and Messenger/WhatsApp are
opt-in per business, subject to a successful eligibility check. The eligibility rules
live in `configs/channel_eligibility.json` — data, not code — so changing them is a
config edit, not a release.

The eligibility engine is written to evaluate rules at **send time**, not at schedule
time. A recipient eligible when the batch was previewed may be ineligible when the
batch fires; the send path re-checks and skips with a recorded reason.

## Fallback

If Messenger and WhatsApp windows turn out to be too restrictive to be worth
supporting, Email and SMS become the only channels. That is a configuration decision,
not a rewrite — the adapter interface does not change.
